# CATWOE

**Category:** [Systems](../../docs/deck.html) &nbsp;|&nbsp; **[← Card Deck](../../docs/deck.html)**

---
## Definition

CATWOE is the analytical core of Peter Checkland's Soft Systems Methodology (SSM) — a six-element checklist for writing a *root definition* of a purposeful human-activity system before anyone redesigns it. The elements: **C**ustomers (who is affected — beneficiaries or victims), **A**ctors (who carries out the activity), **T**ransformation (the core input → output the system performs), **W**eltanschauung (the worldview that makes the transformation meaningful), **O**wner (who can stop or start the system), **E**nvironmental constraints (what the system must take as given). They compose into one sentence: *a system owned by [O], in which [A] carry out [T] for [C], because [W], constrained by [E]*. SSM's premise — and Checkland's distinction between "hard" systems thinking (engineering a system taken as given) and "soft" systems thinking (inquiring into what the system should be) — is that in messy human situations the hard part is not solving the system but agreeing what it is for.

---

## Mental Model

The **W is the crux**. Every definition of a purposeful system smuggles in a worldview that makes its transformation worth doing — and in a contested situation, different stakeholders hold different worldviews, which means they are describing *different systems* while using the same name. People who appear to be arguing about the solution are usually, underneath, disagreeing about the transformation itself. The discipline is to write a separate root definition for each worldview in the room, lay them side by side, and make the disagreement explicit. This converts an unwinnable argument about *what to build* into a tractable argument about *what the system is for and whose purpose it serves* — which can actually be decided, sequenced, or negotiated.

---

## Practitioner Heuristics

- **Start from T, then interrogate W.** Name the core transformation (input → output) first, then ask: *whose worldview makes this transformation worth doing?* The answer exposes the system's hidden purpose.
- **Write multiple root definitions on purpose.** In a contested situation, draft one CATWOE per stakeholder worldview. The set — not any single definition — is the real diagnostic; where the definitions diverge is where the conflict lives.
- **Separate the three "people" roles.** Customers (affected), Actors (do the work), and Owner (can stop it) are routinely conflated. Untangling them often reveals that the person redesigning the system isn't its Owner, or that its Customers were never consulted.
- **The Owner is whoever can kill it.** Test each candidate: could they shut this system down? That names where the real authority — and the real veto — sits.
- **Sort Environmental constraints into fixed and negotiable.** Treating a negotiable constraint as fixed quietly forecloses the best options; treating a fixed one as negotiable wastes effort. Label each.

---

## Common Failure Modes

- **Solving before defining.** Jumping to redesign while stakeholders still hold incompatible transformations — the redesign then satisfies one worldview and is sabotaged by the others.
- **Assuming a single shared worldview.** Proceeding as if everyone means the same thing by the system's purpose. The unspoken differences resurface later as "implementation resistance."
- **Conflating C / A / O.** Collapsing affected parties, doers, and owner into one undifferentiated "stakeholders" loses exactly the distinctions that locate accountability and veto power.
- **Freezing the environment.** Listing constraints as immovable when several are choices — the most common way a CATWOE analysis quietly inherits the very limits it should be questioning.

---

## Worked Example

A company's performance-review system "keeps failing" — every redesign lands, runs for a cycle, and is quietly abandoned. A CATWOE pass writes three root definitions, one per worldview. HR's: *a system owned by HR, in which managers develop people for employees, because growth drives retention and capability.* Finance's: *a system in which managers rank and differentiate staff for the comp committee, because pay must track contribution.* Legal's: *a system in which managers document performance for the company, because decisions must be defensible if challenged.* The three share a name and nothing else — they are three different systems with incompatible transformations, which is why each redesign satisfies one camp and is undermined by the other two. The intervention is not a better form; it is a decision about *which transformation the system primarily serves* — or an explicit separation and sequencing of the three — made by whoever is genuinely the Owner. CATWOE didn't solve the problem; it revealed that "the problem" was three problems wearing one label.
